计费模型TRK-02

协议不替你压缩。你传多少字节，就永久付多少字节的钱。

TapeCode 把站点原样写进链上合约，没有 gzip / brotli / WebP 转换。账单是死的：

常量值含义
CHUNK_BYTES24,000每 24 KB 切一块，一块 = 一笔交易
perChunk270,000 gas每块固定开销（交易本身、目录槽位、事件）
perByte235 gas每一个字节，永久
地板价0.05 gwei（BSC）gasPrice = max(地板价, min(实时价, 20 × 地板价))
单文件上限8 MiB超限文件静默跳过，界面不报错
计费公式
gas ≈ 块数 × 270,000 + 字节数 ×235
参考价1 MB 纯数据 ≈ 0.0129 BNB ≈ $9.60BSC 地板价 0.05 gwei · BNB $747 · 基准 2026-10
币价与拥堵会改变最终金额；改参数后此处实时重算。
多文件比大文件贵

块数按文件各自向上取整。10 个 3 KB 小文件 = 10 块 = 270 万 gas 纯块开销，总共才 30 KB。

只改一个文件，只花那一个文件的钱

同路径 + 同 sha256 会跳过。改动文件整份重传 —— 240 KB 图压到 60 KB，每次改版都省。

别把垃圾传上去

README.md、.map、设计稿照样按字节计费；隐藏文件（.shots/、.DS_Store）整个跳过。

功能说明TRK-03

八件事，每件都带一条证据。

顺序即使用顺序：体检 → 压缩 → 校验 → 账单。

体检 / Checkup

先说清「上传哪些文件、共多少钱」，一个字节都不改。

▸ 只读；列出会跳过 / 断链 / 死文件 / 重复 / Content-Type 问题
压缩 / Shrink

文本压缩、图片重编码、剔除无用文件，默认安全档。

▸ 实测：icon-512.png 246,638 → 55,979（−77%）；chain.js 20,496 → 6,931（−66%）
校验 / Verification

压完自动对拍 10 项，fail 就不让你发布。

▸ 防的是：把内联脚本依赖的 NixieClock 改名 → 一堆 ReferenceError
增量账单 / Incremental bill

只改了一个文件？只算那一个文件的钱。

▸ 同路径 + 同 sha256 跳过；变了的整份重传
预估 / Estimate

「再加一张 2 MB 图要多少？」先算钱，再决定。

▸ 纯计算，不用真的读文件
计费模型 / Gas model

常量、公式、1 MB 参考价，全摊开。

▸ 24,000 B / 块 · 270,000 gas / 块 · 235 gas / 字节 · BSC 地板价 0.05 gwei
三种形态 / Three shapes

网页点一下、命令行一行，或让 agent 走 MCP。

▸ 网页版与 CLI 同一算法，产物字节一致（有测试）
不原地改 / Never in place

源目录只读，产物写到独立的 .tape 目录。

▸ 有断言盯着「源目录零改动」
工作原理TRK-04

四步，全部在本地完成。

01
扫描 / Scan

按路径读一遍，算出文件、字节、块数、gas 和钱，并标出协议会跳过的文件。

02
压缩 / Shrink

文本压缩（顶层名不许改名），图片按 PSNR 门限逐档试，取最小档。

03
校验 / Verify

10 项检查对拍原文：引用、全局名、Content-Type、图片尺寸、体积。

04
出账单 / Bill

前后对比、省下的钱、这一版的增量，产物打包 .tape.zip。

长期成本TRK-06

迭代成本不取决于站点多大，取决于每次改动的那几个文件多大。

同一路径 + 同一 sha256 的文件会被跳过；变了的文件整份重传。
推论：800 KB 站点每次只改一个 20 KB 的 JS，就只付 20 KB。大资源改一次即永久免费 —— 它们是「一次性成本」，代码才是「每次成本」。

边界TRK-07

我们不做的事，也写在页面上。

不做 / SKIPPED
不做字体子集化

字体 176.5 KB，占优化后 44%，最大一项。子集化要重裁字形，且需先有「码位覆盖」校验，否则会变豆腐块。工具只报数：约还能省 88 KB。

不做 / SKIPPED
不直接发交易

只碰文件系统，不发交易、不签名。发布仍走 TapeCode。

不做 / SKIPPED
.well-known/ 传不上去

以 . 开头的路径段被判为隐藏文件、静默跳过，域名验证与 ACME 都不可用。

不做 / SKIPPED
8 MiB 以上的文件界面不报错

协议静默跳过。我们会标出来，发布页不会。

不做 / SKIPPED
改了压缩参数 = 全站重传

参数一变，文件字节可能全变，被判定为全新内容。

不做 / SKIPPED
死文件结论是保守的

只看静态引用；运行时拼出的名字靠 basename / 目录前缀兜底，宁可漏报也不误删。

不做 / SKIPPED
图片质量门限是按 PSNR 量的

PSNR 不是人眼模型。42 dB 只是这几张图看不出差别的位置，换站点建议调高再比。

一个不告诉你边界的压缩工具，不值得把站点交给它。

FAQTRK-09

十一个问题，逐条给答案。

网页版全程在本机浏览器（WebAssembly），一个字节都不外发。服务端 MCP 是另一套入口，需你显式传文件。

不会。站点原样按路径写进链上容器合约，没有 gzip / brotli / WebP 转换。所以「少传字节」是唯一的省钱手段。

默认安全档只改编码、不改路径、不改引用；压完跑 10 项校验，fail 会明确告诉你别发布；源目录全程只读，产物另存。

协议按「路径 + sha256」判断是否跳过。改了压缩参数，几乎每个文件的字节都变，会被当成全新内容整站重传。

这是协议行为：超限文件被静默跳过。我们会替你标出来，发布页不会。

现在不能自动压。字体子集化需要先有「码位覆盖」校验，否则会渲染成豆腐块；工具只报数（实测约还能省 88 KB）。
